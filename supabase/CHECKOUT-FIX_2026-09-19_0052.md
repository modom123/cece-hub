# Fixing "Buy Now goes to inquiry instead of checkout"

## Root cause (diagnosed 2026-09-19)

The website code is already fully wired for checkout — nothing in `index.html`
needs changing. The buttons fell back to the inquiry form because of **data +
deployment**, not code:

1. The Supabase **`pieces` table is empty**. When it's empty the site shows its
   built-in demo catalog (`sampleData()` in `index.html`) whose piece IDs
   (`cat-plaque`, `cat-ocean`, …) **do not exist in the database**.
2. Clicking Buy Now calls the `create-checkout` Edge Function with one of those
   fake IDs → the function returns **"Piece not found"** → the site shows the
   "not set up for online checkout yet" message and opens the **inquiry form**.

So Buy Now reaches real Stripe checkout only when **all three** are true:

- [ ] Real pieces **with prices** exist in the `pieces` table (valid IDs)
- [ ] `create-checkout` Edge Function is **deployed**
- [ ] `STRIPE_SECRET_KEY` secret is set on a key that can **create Checkout Sessions**

## Step 1 — Put real pieces in the database

Fastest: open Supabase → **SQL Editor** → paste and run
`migrations/seed_pieces_2026-09-19_0052.sql`. It seeds the full catalog
(idempotent — safe to re-run) using the same prices shown on the site today.
Edit the prices in that file (or later in the Business Hub) to your real prices.

(Alternative: add pieces one-by-one in the Business Hub's Publish form — that
also creates valid rows.)

## Step 2 — Deploy the checkout function and set the Stripe key

Install the Supabase CLI (`npm i -g supabase && supabase login`), then from the
`cece-hub` repo root:

```bash
supabase link --project-ref tssicoxzxcfijdlvtpqm

# Set the Stripe key HERE (never paste it into chat or commit it).
# The restricted key must have WRITE access to "Checkout Sessions"
# (plus Prices / PaymentIntents) — a read-only "transactions" key will 500.
supabase secrets set STRIPE_SECRET_KEY=rk_live_xxxxxxxx
supabase secrets set SITE_URL=https://cecespieces.com    # your live site URL

supabase functions deploy create-checkout
supabase functions deploy stripe-webhook --no-verify-jwt # marks pieces sold on payment
```

See `functions/STRIPE-SETUP.md` for the webhook endpoint + signing-secret setup
and the custom-piece deposit/invoice flow.

## Step 3 — Verify

In PowerShell, confirm the function now returns a checkout URL for a real piece:

```powershell
$SUPA = "https://tssicoxzxcfijdlvtpqm.supabase.co"
$KEY  = "<anon key from index.html>"
$h = @{ apikey = $KEY; Authorization = "Bearer $KEY" }
$p = (Invoke-RestMethod "$SUPA/rest/v1/pieces?select=id,title,price&limit=1" -Headers $h)
$body = @{ piece_id = $p.id } | ConvertTo-Json
Invoke-RestMethod "$SUPA/functions/v1/create-checkout" -Method Post -Headers $h -ContentType "application/json" -Body $body
```

Expected: `url = https://checkout.stripe.com/...`. Then on the live site, a
priced piece's **Buy Now — $X** goes straight to Stripe.

Test with Stripe **test keys** first (card `4242 4242 4242 4242`), then switch to
live keys.

## Notes

- **Statement Panel** pieces intentionally route to inquiry ("Inquire for Your
  Size") because they're custom-sized — that is by design, not a bug.
- Pieces with a **deposit** set (e.g. Ocean Islands) charge the deposit now and
  invoice the balance later — see `STRIPE-SETUP.md` §5b.
- **Rotate any Stripe key that was shared in plain text**, then set the fresh one
  with `supabase secrets set`.
